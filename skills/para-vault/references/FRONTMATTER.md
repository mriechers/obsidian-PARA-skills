# FRONTMATTER — worked examples

Copy-paste-ready frontmatter for each note type. Property *syntax* and rules →
[obsidian-markdown](../../obsidian-markdown/SKILL.md); the binding vocabulary
(anchor tag, `para` enum, `status` values) → [VAULT-CONFIG.md](VAULT-CONFIG.md) §3.

Every note starts `tags` with the anchor tag **`all`**, then lowercase kebab-case
topical tags. `para` is ground truth (not the folder). `created` is `YYYY-MM-DD`
(optionally `YYYY-MM-DD HH:mm`).

## Inbox capture

The minimal contract — what `/add-to-inbox`, vault-courier, and any out-of-app
write must produce.

```yaml
---
tags:
  - all
created: 2026-07-06 17:32
para: inbox
---
```

## Project (with `status`)

```yaml
---
tags:
  - all
  - freelance-biz
created: 2026-07-09
para: projects
status: active
---
```

`status` must be one of the observed vocabulary (VAULT-CONFIG §3): `active`,
`unprocessed`, `incubating`, `draft`, `waiting`, `parked`, `ready`, `prototyping`,
`processed`, `planning`.

## Archived note

**Move the file into `4 - ARCHIVE/<year>/`** — do not set `para: archive` by
hand. quick-para's `rename` handler derives `para` from the folder, sets
`archived:` (once, never cleared), and appends the `para_history` entry.
Hand-editing `para` is reverted on the next pass and forges a fake transition
(see SKILL.md, "Moving notes between PARA categories").

Note that **auto-cancel-on-archive does not actually run** — the deployed build
drops its task manager through a constructor-arity bug, so open tasks survive
archival despite the sidebar dialog promising otherwise. Cancel them explicitly
if it matters.

Below is what a correctly archived note ends up carrying, not what to write by
hand. `status` is often stale here — it is write-once and never updated on
archival (`status: active` survives into the Archive on 66 notes), so don't read
it as current.

```yaml
---
tags:
  - all
  - job-search
created: 2025-11-02
para: archive
status: processed
archived: 2026-08-07
---
```

## Daily journal

Generated by `journal-template.md`; filename `YYYY-MM-DD.md`. `generated_sections`
is the briefing engine's injection hook — leave it as an empty string.

```yaml
---
tags:
  - all
  - daily-journal
para: inbox
created: 2026-07-08
generated_sections: ""
---
```

## Clipping / Readwise note

Readwise and web-clipping notes add intake metadata on top of the contract.
vault-courier always adds `source`.

```yaml
---
tags:
  - all
  - internet-clipping
created: 2026-07-09
para: resources
source: https://example.com/article
content-type: article
intake: readwise
creator: Jane Author
published: 2026-06-30
share-url: https://readwise.io/reader/...
---
```

## `para_history` entry schema

**Plugin-written by quick-para. Append-only. Never hand-edit, reorder, or delete
entries.** Shown for recognition only.

```yaml
para_history:
  - from: inbox
    to: areas
    date: 2026-07-02
    timestamp: 1783034439389
```
